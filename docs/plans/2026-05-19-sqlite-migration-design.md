# SQLite migration — alternate/db branch

**Date:** 2026-05-19
**Branch:** alternate/db
**Status:** Implemented in this branch.

## 1. Goal

Replace MongoDB with SQLite as the persistence layer for REServer and
REDataLoader. Keep the public HTTP API and its response shape unchanged so
existing clients (Postman collection, teammate scripts) keep working.

`main` continues to use MongoDB. This branch demonstrates a swap to a fully
relational store — single-file embedded DB, no separate process.

## 2. Stack

- **Driver:** `org.xerial:sqlite-jdbc` (single Maven dep, ships JDBC driver).
- **Access:** plain JDBC + prepared statements. No JPA / Hibernate / ORM.
- **Connection:** one `Connection` per DAO, opened in constructor, kept open
  for app lifetime. SQLite is fine with a long-lived connection in a single
  JVM; we serialize concurrent access via a shared `Db` helper.
- **Config:** new env var `SQLITE_PATH` replaces `MONGO_URI`. Default
  `/data/re-server.db` (matches the Docker bind mount).
- **Pragmas on open:** `foreign_keys = ON`, `journal_mode = WAL`,
  `synchronous = NORMAL`, `busy_timeout = 5000`.

## 3. Schema

Normalized relational schema (chosen over a flat per-collection mirror).
All hex-string PKs are preserved so the HTTP API still returns the same
24-character `"abc123..."` IDs that Mongo did — the wire format does not
change. New IDs are random 24-char hex strings (generated by
`ObjectIdLike.next()` — same shape as `ObjectId.toHexString()` without
pulling in the Mongo BSON library).

```sql
CREATE TABLE postcodes (
  post_code     TEXT PRIMARY KEY,
  search_count  INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE properties (
  id              TEXT PRIMARY KEY,
  property_id     INTEGER,
  post_code       TEXT NOT NULL REFERENCES postcodes(post_code),
  purchase_price  INTEGER,
  address         TEXT,
  council_name    TEXT,
  property_type   TEXT,
  contract_date   TEXT,
  for_sale        INTEGER NOT NULL DEFAULT 0,
  search_count    INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_properties_post_code      ON properties(post_code);
CREATE INDEX idx_properties_purchase_price ON properties(purchase_price);
CREATE INDEX idx_properties_property_id    ON properties(property_id);

CREATE TABLE accounts (
  id            TEXT PRIMARY KEY,
  name          TEXT NOT NULL,
  email         TEXT NOT NULL UNIQUE,
  account_type  TEXT NOT NULL
);

CREATE TABLE postcode_interest (
  account_id  TEXT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  post_code   TEXT NOT NULL REFERENCES postcodes(post_code),
  PRIMARY KEY (account_id, post_code)
);
CREATE INDEX idx_pi_post_code ON postcode_interest(post_code);

CREATE TABLE listings (
  id            TEXT PRIMARY KEY,
  property_id   TEXT NOT NULL REFERENCES properties(id) ON DELETE CASCADE,
  is_discounted INTEGER NOT NULL DEFAULT 0,
  date_added    TEXT NOT NULL
);
CREATE INDEX idx_listings_property ON listings(property_id);

CREATE TABLE listing_prices (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  listing_id  TEXT NOT NULL REFERENCES listings(id) ON DELETE CASCADE,
  price       REAL NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX idx_prices_listing_date ON listing_prices(listing_id, updated_at DESC);

CREATE TABLE purchases (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id   TEXT NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  property_id  TEXT NOT NULL REFERENCES properties(id) ON DELETE CASCADE,
  purchased_at TEXT NOT NULL
);
```

### Differences from the Mongo shape

| Concern | Mongo | SQLite |
|---|---|---|
| Row ID | `ObjectId` | hex string (`TEXT`) — same wire format |
| Account postcodes | `postcode_interest: [String]` array | `postcode_interest` junction table |
| `postcode_stats` | sibling collection | `postcodes.search_count` column |
| `property_pricing_updates` keyed by `pid` (property) | keyed by `listing_id` (cleaner) |
| `for_sale` flag | boolean field | `INTEGER 0/1` (SQLite has no native bool) |

Postcode FK on properties means the loader must insert every distinct CSV
postcode into `postcodes` before inserting properties. `ensurePostcode` is
also called by DAOs that accept postcodes from user input (purchaser create,
add-interest, seed).

## 4. Code layout

```
REServer/src/main/java/
├── db/
│   ├── Db.java               # JDBC connection + schema init + helpers
│   └── ObjectIdLike.java     # 24-char hex ID generator (Mongo ObjectId shape)
├── property/                 # unchanged controllers + models; DAO rewritten
├── listing/                  # same
├── purchaser/                # same
├── notify/                   # same
└── app/REServer.java         # constructs DAOs against shared Db
```

`Property.propertyID` switches type from `ObjectId` to `String` — only the
field type changes; existing controller code uses `.toString()` so it still
compiles.

## 5. Data loader

`REDataLoader/Main.java` rewrites the CSV → DB path:

1. Open SQLite at `SQLITE_PATH`.
2. `DROP TABLE IF EXISTS` + re-create schema (matches REServer's `Db.init`).
3. Stream CSV rows. For each row:
   - `INSERT OR IGNORE INTO postcodes (post_code) VALUES (?)`
   - `INSERT INTO properties (...)` with a freshly generated hex `id`.
4. Batch with `addBatch()` / `executeBatch()` every 1000 rows, inside a single
   transaction (auto-commit off) so the bulk load is fast (~25k rows/sec on
   SQLite WAL).
5. Drop + recreate indexes at the end (faster than maintaining during load).

## 6. Docker

- Drop the `mongo` service and the `local` profile.
- Bind-mount `./data:/data` for the server (DB file) and loader (DB + CSV).
- Server `Dockerfile` adds `VOLUME /data`.
- `docker compose up server` boots; if `re-server.db` does not exist, the
  server creates it empty and the loader can populate it.

## 7. Config + docs

- `.env.example` replaces `MONGO_URI` with `SQLITE_PATH=/data/re-server.db`.
- `README.md` updated to describe the SQLite flow.

## 8. Tests

`notify.NotifyServiceTest` already passes pure inputs (no DB) — keeps
working untouched. No new tests added in this migration (out of scope; the
build verifies wiring).

## 9. Out of scope

- Multi-backend abstraction (Repository pattern). The brief asked for the
  easiest swap; `main` keeps Mongo, this branch is SQLite-only.
- Schema migrations / versioning. We `DROP + CREATE` on loader run; the
  server's `Db.init` only `CREATE IF NOT EXISTS` so a populated DB is not
  destroyed when the server boots.
- Connection pooling. SQLite + single JVM + one connection per DAO with WAL
  is sufficient for course-level traffic.
